# Pinned dependency lock for this repo's exact runtime closure.
#
# docs/evaluation.md's Showpad engineering-rigor assessment (2026-08-08,
# Band 1) found this precisely: 'Dependency locking is floating' --
# pyproject.toml and requirements.txt both use unpinned >= constraints,
# so two installs at different times could resolve completely different
# transitive versions. This file is the fix: generated via a clean,
# throwaway virtualenv (not this shared dev machine's own Python install,
# which has ~479 packages from unrelated projects mixed in), CONSTRAINED
# to prefer whatever this dev machine's main environment already had
# installed (`pip freeze` there, minus any `-e ` local-path lines pip's
# `-c` flag rejects), then frozen -- so every version below is one this
# repo's own test suite has actually been run against, not just "resolves
# cleanly today." The constraint step is not optional: a bare, unconstrained
# `pip install -e .` in a fresh venv resolved `starlette==1.4.1` /
# `fastapi==0.141.1` here -- current-on-PyPI, but neither version has ever
# been imported by this repo's tests (which ran all session against
# starlette 0.50.0 / fastapi 0.128.2). `pip-compile` hit the identical
# failure mode earlier in this same pass. Both tools optimize for "resolves"
# over "matches what's tested" unless explicitly told which versions to
# prefer -- hence the constraints file below.
#
# requirements.txt (the abstract >= ranges mirroring pyproject.toml)
# remains what the Dockerfile installs from day to day -- this file is
# the point-in-time source of truth for "what versions has this actually
# been run against," regenerate it after intentionally upgrading a
# dependency, not automatically on every install.
#
# Regenerate (run from an environment where the test suite has actually
# been run recently -- that's the constraint source):
#   pip freeze | grep -v '^-e ' > /path/to/constraints.txt
#   python -m venv /path/to/lockenv
#   /path/to/lockenv/bin/pip install -e . -c /path/to/constraints.txt
#   /path/to/lockenv/bin/pip freeze | grep -v '^-e ' > requirements.lock.txt
# (dev extras: also pip install -e '.[dev]' -c constraints.txt first if
# locking those too)
